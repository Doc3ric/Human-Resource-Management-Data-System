## Per-module findings

**Module 1 (Active Status Gate) / Module 1A (Renewal Signal Architecture)** — substantially built: `renewal_signals` + `contract_renewals` tables, `RenewalSignalService` (signal recording, AUTHORITATIVE/CORROBORATING split matches spec 1A.3 exactly), `RenewalCommitService` (single commit path — vacancy check, duplicate-period check, forces `is_renewed=true`, logs to `ActivityLog`, matches spec 1A.6), `RenewalAuthority` (gates on the existing `add Batch Renewal` permission bit rather than inventing a parallel one — a reasonable, documented reuse decision), `BatchRenewalController::requestRenewal()` (Module 1A.8's Request-to-Renew flow, routed at `plantilla/{id}/request-renewal`). `RenewalGateTest` passing.
**Real gap found:** `resources/views/components/renewal-status-widget.blade.php` (Module 1A.5's "ONE shared embeddable widget") exists, is fully built and self-contained, and is referenced **nowhere** — zero includes across the entire `resources/views` tree. The spec requires it to appear "wherever an employee with is_renewed=false appears (performance tracker, records view, batch renewal, personnel inventory)"; today it appears in none of them.

**Module 1B (Lifecycle Exclusion & Retention Matrix)** — `lifecycle_status` + `lifecycle_effective_date` + `lifecycle_basis` columns exist on `plantilla_records` (migration `2026_07_02_120001`). `retention_schedule` table + `RetentionScheduleController` (index/store/update/exportCsv) exist and are seeded (`RetentionScheduleSeeder`). `LifecycleRetentionTest` passing.
**Real gap found:** Spec 1B.4 ("keeps hard-delete locked until the signed NAP Form No. 3 is uploaded and verified... permanent records never eligible for disposal") is not enforced anywhere for personnel records. `ArchiveController::forceDelete()` performs an unconditional `$model->forceDelete()` gated only by `role:super_admin` route middleware — no NAP Form 3 upload/verification step, no permanent-record check, no reference to `retention_schedule` at all. This is a direct violation of this project's own CLAUDE.md Absolute Rule #4 ("No unguarded DELETE/DROP. Destruction is soft-delete to an audited disposal workflow gated by signed-authority upload (NAP Form No. 3)"), not just a spec nice-to-have. The IDCC side (`documents`/`document_retention_rules`) has the right shape for this (`is_permanent`, `disposal_requires_ledger_verification`); the personnel-records side (`ArchiveController`) never adopted it.

**Module 2 (Recruitment View & NAP Retention)** — **not built.** No `is_filled`/`date_filled` columns exist anywhere (checked `plantilla_records` migrations and model) despite `HRDMS_PHASE0_FOUNDATION.txt`'s own Step 1 explicitly listing them as columns that should already exist. No 3-stage (Active/Archived/Valueless Holding Queue) lifecycle command, no Disposal View for this record class. Re-reading the spec text closely: this module is about **vacant plantilla positions** ("vacancies track is_filled boolean and date_filled timestamp... tie records to item_number") — i.e., `plantilla_records`, which is squarely Track A's owned table region per the ownership matrix — not the `applicants` table, which belongs to Track B. This resolves what first looked like a track-boundary conflict: Module 2 is legitimately buildable by Track A as additive, nullable columns on `plantilla_records` plus a new read-side view/command, without touching any Track-B-owned file.

**Module 2B (Leave Violation Monitoring)** — very thoroughly built. `LeaveViolationDetectionService` (AWOL 30-day threshold, habitual tardiness/absenteeism), `LeaveViolationLetterService` with templates for AWOL/Return-to-Work Order, Habitual Tardiness, Habitual Absenteeism, LWOP, LWOP+Tardiness, Reprimand (tardiness/undertime), and all three late-filing categories (sick Sec. 53, vacation Sec. 51, other), each with the correct legal citation. Payroll coordination (`issuePayrollCoordination`, DROP vs. salary-deduction-for-information) implemented and routed. `LeaveViolationTest`/`LeaveFilingViolationTest` passing. No material gap found.

**Module 3 (Data Integrity & Plantilla Sync)** — `PlantillaSyncValidator` exists with the exact spec-quoted "Plantilla Mismatch Block" message (3.2). Vacant-positions dropdown queries use `DISTINCT`/`orderBy` consistently across `PlantillaController`. `PlantillaSyncValidatorTest` passing. **Boundary note (pre-existing, not introduced by this session):** `PlantillaSyncValidator` reads the `Applicant` model — a Track-B-owned table per the ownership matrix ("Track A does not reference these") — to compare against the master Plantilla record. It's read-only and already built/tested; ripping it out to enforce the letter of the boundary would break a working, spec-required feature (comparing an applicant's snapshotted position data against the current Plantilla master requires reading the applicant). Flagged, not touched.

**Module 3A (Incident Report / AI-Assisted Counseling)** — thoroughly built. `RulesAdvisoryEngine` (advisory-only, non-removable label matching spec verbatim), dual track (`final_track` counseling/escalated) with `incident_escalate`-permission gate on escalation, conflict-of-interest guard (`abort(403, ...)` when the finalizer is an involved party) matching spec 3A.7 exactly. `IncidentReportTest` passing. No material gap found.

**Module 10 (Track A portion — M1 Records / M2 Leave)** — M1 (Records/201-file) is Phase 0's IDCC core, already built and out of Track A's scope to modify. M2 Leave: `leave_types`/`leave_balances`/`leave_applications`, accrual service present, JO/COS guardrail present (per Phase 0 discovery). `LeaveModuleTest` passing. No material gap found.

**Module 10B (Learning & Development)** — training capture, attendance (including `is_resource_speaker` flag), individual + batch certificate issuance (`TrainingCertificateService`), distinct resource-speaker certificate type, auto-link to employee record via IDCC, `TrainingModuleTest` passing.
**Real gap found:** Module 10B.5's no-code certificate template customization (named templates, logo/font/signatory configuration, live preview) does not exist anywhere — no `CertificateTemplate` model/migration/controller. Core certificate issuance works against a fixed layout only.
