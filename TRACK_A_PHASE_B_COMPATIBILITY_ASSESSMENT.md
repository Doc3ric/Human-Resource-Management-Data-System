This assessment covers only the 4 real gaps `TRACK_A_PHASE_A_DISCOVERY_REPORT.md` found; every other Track A module is already built, tested, and untouched by this plan.

| Gap | Fit | Existing-feature impact | Field/table mapping | Risk | Dependencies |

Renewal Status Widget orphaned (1A.5)** | Clean — the component already exists and is self-contained (`<x-renewal-status-widget :record="$plantilla" />`); this is purely an adoption task (embed it), not a build task. | None on data/logic — purely additive markup in 3 existing view files. ## Decision on scope for this pass

Given the size difference between these four items, Phase C sequences them by risk-adjusted value: (1) and (3) are contained and high-confidence; (2) is the one item that's actually a standing violation of this project's own Absolute Rule #4, so it gets priority despite being the riskiest; (4) is real but is an optional customization layer on an already-fully-functional feature (certificates generate correctly today), so it's the one gap this pass defers, with reasoning recorded rather than silently dropped — consistent with how Phase 0's gap-closing pass handled similarly-scoped deferrals.
