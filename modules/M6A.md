MODULE 6A — HRMPSB DELIBERATION MONITORING BOARD
Additive to Modules 5–6. Do not alter existing scoring logic, twg_scores writes, the blind scoring ID, or panel behavior. Live completeness/accountability tracker showing, in real time, which HRMPSB member has or has not scored which applicant for the vacant position currently being deliberated. Shows completion STATE only, never numeric score values (preserves independent evaluation under 2025 ORAOHRA Rule IX and member confidentiality under CSC MC No. 03 s.2001).
6A.1 Placement: a third region — a collapsible drawer or toggleable tab labeled "Monitoring Board" pinned to the deliberation workspace fixed header — without disturbing the 45% left profile and 55% right scoring panels. Collapsed by default below 1280px; expanded as a right-edge drawer or full-width strip below the applicant selector on wider screens. Opening it never resets the active scoring session.
6A.2 Scope: always bound to the single active vacancy_id; never aggregates across vacancies; reloads its members/applicants when the deliberated position changes.
6A.3 Data sources (read-only aggregation; never duplicate score data): the HRMPSB panel members assigned to this vacancy/session; the applicants populating the selector chips; and twg_scores for completion state. If no panel-membership table exists, propose hrmpsb_panel_members (panel_member_id, vacancy_id, user_id, member_role ENUM('CHAIRPERSON','REGULAR_MEMBER','ALTERNATE','SECRETARY'), is_active BOOLEAN) and surface for approval before creating.
6A.4 Completion states per member per applicant: Not Started (no saved row) var(--color-danger); In Progress (Save Draft used, not submitted) var(--color-warning); Scored (submitted/locked evaluation exists) var(--color-success). Display state only — never the numbers.
6A.5 Three views via a switcher: (1) MATRIX (default) — members x applicants grid of status dots; applicants shown by blind scoring ID (DDMMYY&ItemNo), never raw names; hover shows "[Member] — [Applicant masked ID] — [Status] — [last action time]"; row/column completion fractions (e.g., 3/5). (2) BY MEMBER — per member progress bar ("Member A — 4 of 6 scored, 2 remaining"), expandable to the specific owed applicants; complete members show a green check. (3) BY APPLICANT — per applicant progress bar ("scored by 5 of 7 members, 2 pending"); an applicant is comparison-ready only when all active members have submitted.
6A.6 Live summary strip (all views): total active members, total applicants, total required evaluations (members x applicants); completed count + overall % with a var(--color-success) bar; In Progress and Not Started counts; readiness indicator — "Position ready for comparative deliberation" (var(--color-success)) only when every active member has submitted for every applicant, else "Awaiting [N] evaluations" (var(--color-warning)).
6A.7 Real-time refresh: lightweight polling every 10–15s of a states-only aggregation endpoint (SSE/websocket only if the existing stack already supports it — confirm in Phase A; no heavy new infrastructure without approval). Refresh updates dots, fractions, bars, readiness without reloading or disturbing the active scorer; show "Last updated [HH:MM:SS]" and a manual "Refresh now".
6A.8 Reminders: (a) Personal banner — when a member works in the workspace with unscored applicants for the active vacancy, show a dismissible var(--color-warning-bg) banner "You have [N] applicant(s) not yet scored for this position: [masked IDs]…"; clicking a masked ID loads that applicant into the panels. (b) Per-member nudge (Chairperson/Secretary only) — a "Remind" control beside any incomplete member queues an in-system notification; use an existing notification facility if present, else an in-app toast/notification-center entry; no external email/SMS unless an existing approved service exists; every reminder is audit-logged. (c) Closing guard — when the Chairperson marks the phase [Completed] while any active member has unscored applicants, intercept: "Warning: [N] evaluations are still incomplete ([members]). Closing now will proceed without their scores. Continue or return to deliberation?"; proceed only on explicit confirmation, logged to audit (informed-decision, not auto-block).
6A.9 RBAC/visibility: Regular/Alternate Members see completion states (dots, fractions, readiness) and their own banner, never others' score values, and cannot remind others; Chairperson/Secretary additionally get Remind controls, the closing guard, and snapshot export; AE and non-panel roles have no access (consistent with Module 4). All board access is logged. No role ever sees numeric scores via the board.
6A.10 Export (Secretary/Chairperson): "Print/Export Monitoring Snapshot" — header "Provincial Government of Bukidnon — PHRMO — HRMPSB Scoring Activity Monitor"; position title, item number, office, date/time, generating user; the member x applicant completion matrix (masked applicant IDs, member names); summary statistics; footer "Reflects scoring completion status only. Score values are confidential under R.A. 10173 and are compared only during formal board deliberation. 2025 ORAOHRA Rule IX." Serves as a minutes attachment evidencing evaluation completeness.
6A.11 Audit/compliance: log board opens by user+vacancy; log every reminder and every closing-guard override; the board must never display, export, or leak numeric scores or recommendations — completion states only — until the existing formal comparison step runs. Tooltips cite 2025 ORAOHRA Rule IX on the board header and CSC MC No. 03 s.2001 on the reminder and export controls.
